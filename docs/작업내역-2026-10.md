> 푸시되어 있다. 이 문서는 "무엇을·왜·어떻게 되돌리나"를 사람이 읽기 위한 요약이다.

## 배경

데이터를 전수 실측하다 크롤러의 한 줄을 발견한 게 시작이었다.

```js
// crawl-wikipedia-folklore.mjs:685 (수정 전)
const engDesc = (article.extract || '').substring(0, 100).replace(/\n/g, ' ');
```

위키 원문을 **단어 경계를 무시하고 100자에서 하드컷**하고 있었다. 실측하니 119~124자 구간에
3,535건이 몰려 있었고, 그중 1,709건이 영문 단어 중간에서 끊겨 있었다. `Cherub`은
`"is one type of supernatura"`로 끝났다.

여기서 시작해 번역·분류·이미지·게이트로 문제가 연쇄적으로 드러났다.

## 1) 설명 절단 — `3492c60`, `b97d6ed`

### 크롤러 수정

`clipExtract()`를 신설했다. 문장 경계 우선, 없으면 단어 경계에서 자르고 `…`를 붙인다.
약어 마침표(`c. 1300`, `e.g.`, `pl.`)를 문장 끝으로 오인하지 않는다.
재현 테스트 `scripts/test-description-truncation.mjs` (8케이스).

### 2차 피해도 있었다

스코틀랜드 호수괴물 `Muc-sheilche`가 2026-08 게이트 회귀에 걸린 이유가 이 버그였다.
설명이 `"is a lake monste"`로 잘려 게이트의 생물어 판정(`NC_BEING`)이 실패한 것이다.

### 기존 데이터 복구

하드컷 대상 4,096건(영문 100자 + 한국어 200자)을 위키 원문으로 재수집했다.
수집 97.6% 성공(3,998건), API 오류 0. 적용 3,974건, **적용분 100%가 문장이 제대로 끝난다.**

- 1단계 `scripts/repair-truncated-desc.mjs` — 수집만, 데이터 미변경, 재개 가능
- 2단계 `scripts/apply-desc-repair.mjs` — 런로그를 읽어 적용
- 런로그 `runlogs/desc-repair-20260822.jsonl`, `desc-repair-apply-20260822.jsonl`

### 오매칭 방지가 핵심이었다 — 재사용 가치가 있는 판정법

위키 문서는 크롤 이후에도 편집된다. `prefix` 완전일치만 요구하면 정당한 문서를 놓치고,
느슨하게 하면 엉뚱한 문서가 들어온다. 2단으로 판정했다.

| 판정 | 조건 | 비고 |
|---|---|---|
| strong | 위키 원문이 기존 잘린 조각으로 시작 | 3,879건 |
| weak | 고유 토큰 겹침 0.65 이상 | 97건, **전수 육안 검증** |

실측 사례:

- `A kumiho or gumiho` → `A gumiho or kumiho` (어순 변경, 제목도 Gumiho로 이동) — strong 실패, weak 구제
- `Seonangshin` — 이표기가 추가됨 — weak 구제
- **영문 위키의 `Arang`은 지금 한국 설화가 아니라 인도 차티스가르의 마을 문서다** — prefix 검증이 막아냈다

weak 97건을 전수 확인해 **오매칭 2건**을 찾았다. `Grani`(시구르드의 **말**)에 Sigurd(영웅) 문서를,
`Decima`(로마 파르카이)에 Moirai(그리스 운명의 세 여신) 문서를 가져온 건이다.
둘 다 **검색 폴백 출처**였으므로 weak+검색폴백 조합 5건을 통째로 제외했다
(그중 3건은 옳은 매칭이지만 버려도 현상 유지일 뿐이라 이 교환을 택했다).

미복구 122건은 위키 문서가 크게 바뀌었거나 사라진 것이다. 손대지 않았다.

## 2) 재번역 — `897e5ae`, `e8b7ed1`

정본 `d`를 고쳐도 상세 페이지는 바뀌지 않는다. `trans?.d || creature.d`로 번역본을 우선 쓰는데,
그 번역본은 잘린 원문을 번역한 것이었다. `translate-creatures.mjs`는 기존 번역이 있으면
건너뛰므로(메인 루프의 `if (result[c.id]) continue;`) `invalidate-translations.mjs`로 대상을
무효화한 뒤 재번역했다.

ko 2,890 + zh 3,950 + ja 3,960 = **10,800건**. 이후 존댓말 잔여 112건 추가.

### 시험 20건이 4천 건짜리 사고를 막았다

그냥 돌렸으면 전부 박혔을 문제 셋을 시험 단계에서 잡았다.

| 문제 | 실제 출력 | 대책 |
|---|---|---|
| 존댓말 | "~입니다" (기존 4,856건은 평서체) | 프롬프트에 언어별 문체 못박음 (ko 평서체 / ja 常体 / zh 서면어) |
| 유형 라벨 오역 | `Spirit` → **"영혼"** (장승은 신령이고, 사이트 필터가 쓰는 분류 라벨이다) | 28종 유형명 영문 고정 |
| 지명 오역 | `Heaven Lake`(천지) → **"하늘"** | 의미 기준 번역 지시 |

### 실행 중 드러난 스크립트 결함 셋

| 결함 | 증상 | 대책 |
|---|---|---|
| 청크 유실 | 깨진 JSON이 오면 catch가 재시도 없이 넘어가 **20건이 통째로 사라졌다** (실측 140건) | 재시도 3회 → 청크 이분할 → 문자열 내 제어문자 복구 |
| 키 변조 | LLM이 id까지 번역 (`br-headless-mule` → `br-无头骡`, `gb-실낙원` → `gb-实乐园`). 고아 키 13건 발생 | 응답 키가 요청 키에 없으면 폐기 |
| 접두사 오역 | 한국어 '설화'가 한자로 음역 — zh `世界设话中出现的`(设话는 중국어에 없는 말), ja `世界設話に登場する`(표기는 説話, 조사 の 누락) | `scripts/fix-i18n-prefix.mjs`로 zh 1,381 · ja 1,372건 일괄 교정 |

접두사 오역은 **재번역 이전 데이터에도 있던 결함**이었다 (zh `设话` 201건, `设法` 95건).

프롬프트 수정은 봇이 쓰는 스크립트에 들어갔으므로 앞으로 크롤되는 항목도 같은 문체·용어로 번역된다.

### i18n 구조 오염도 정리했다

zh에 `ab`·`wk`·`sh`가 **최상위 키**로 들어가 있었다. 능력/약점/스토리훅 필드가 구조 밖으로
새어나온 것으로, LLM이 JSON 구조를 잘못 만든 흔적이다. `fr-卢브尔-皮拉米德`처럼 id 자체가
번역된 고아도 있었다. 런로그 `runlogs/i18n-orphan-cleanup-20260824.jsonl`.

**현재 i18n 3종 모두 4,821건으로 종 수와 정확히 일치한다.**

## 3) 이미지 조회 버그 — `c136c96`

`getCreatureImage()`가 국가 접두사를 `/^[a-z]{2}-/`로 벗겼다. `sct-`(스코틀랜드 73종),
`wls-`(웨일스 67종)는 **3글자**라서 이 140종은 이미지가 있어도 표시되지 않았다.

단순히 `{2,3}`으로 바꾸면 안 된다. `wls-gwyllion`처럼 **id 전체가 맵 키**인 이미지 2건을 잃는다.
3글자 → 2글자 → 원본 id 순으로 시도하는 **폴백 체인**으로 고쳤다. 신규 연결 29건, 손실 0.

이 버그는 고아 판정도 오염시켰다. 2글자만 가정한 초기 스캔에서 고아 72건이 나왔지만,
**48건이 살아있는 종을 고아로 오판한 것**이었다.

## 6) 게이트 사각지대 — `a7c6299`

기존 게이트(`looksNonCreatureSubject`)는 **영문 extract의 계사 보어만** 검사한다.
그래서 설명이 한국어·일본어·중국어로만 된 기사는 검사 자체를 통과했다.
**실측 3,669건이 이 사각지대에 있었다.** 「전설의 고향」 드라마 5종이 살아 있던 원인이다.

`looksNonCreatureSubjectCJK()`를 추가했다. 영문판과 같은 하드/소프트 구조다.

- **하드** (존재어가 있어도 차단) — 방송·영상, 향가·악장·악곡, 무덤·사찰, 민속학자·정치인, 사자성어
- **소프트** (존재어가 같은 문장에 있으면 통과) — 서적·장소·학자·의례·개념

재현 테스트 `scripts/test-cjk-gate.mjs` (reject 14 / pass 14).

### 설계 판단 두 가지

**개별 이야기는 막지 않는다.** 도감이 `t=Folktale`로 담기로 한 대상이고, 영문 게이트도
`anthology`/`collection`은 막되 개별 tale은 통과시킨다. 작품집(설화집·선집·전집)과
설화가 아닌 장르(향가·악장·악곡)만 막는다. 「흥부전」·「서유기」는 통과한다.

**`"~을 일컫는 말이다"`는 앞 수식어를 요구한다.** 그냥 `말이다`로 잡으면
「하늘을 나는 신성한 **말**이다」(馬)가 걸린다.

### 오차단 함정 둘 (테스트에 고정)

- `천마` — `말이다`(馬)가 사자성어의 `말`(語)에 매칭됐다
- `오메테오틀`·`가미노요나나오` — 「**신들**을 묶어 이르는 말」, 「**부부신**」이 존재어로
  인식되지 않아 아스텍·일본 신이 차단됐다. 신격 총칭을 `CJK_BEING`에 추가했다

### 이미지 파일을 지우지 않은 이유

마지막 9건(약 2MB)의 파일은 남겼다. 이미지는 크레딧을 들여 생성한 자산이고,
`quetzalcoatl`·`mahakala` 같은 유명 존재는 앞으로 크롤로 다시 들어올 수 있다.
그때 파일이 있으면 맵에 등록만 하면 되지만, 지우면 재생성에 다시 크레딧이 든다.

**의도적 보존이다. "잔여물"로 보고 지우지 마라.**

## 되돌리는 법

전부 git에 있다. 커밋 단위로 `git revert` 하면 된다.

데이터 변경은 런로그에 이전 값이 남아 있다. `runlogs/*.jsonl`의
`oldD`(이전 설명), `from`(이전 유형), `n`·`t`·`iso`(삭제된 종 정보)를 읽어 복원 스크립트를 짤 수 있다.

삭제된 종의 본문까지 되살리려면 해당 커밋의 부모에서 정본을 꺼내는 게 빠르다.

```bash
git show ee8dcc8^:lib/folklore-data.ts > /tmp/before.ts
```
